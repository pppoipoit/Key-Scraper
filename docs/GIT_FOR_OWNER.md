# Git สำหรับเจ้าของโปรเจกต์ที่ไม่เขียนโค้ด

Git เปรียบด้วยระบบเซฟเกมในแอป:
- Repository = โฟลเดอร์เกมที่มีไฟล์ทั้งหมดของโปรเจกต์
- Commit = จุดเซฟที่บันทึกว่าตอนนี้มีอะไรอยู่ในโปรเจกต์
- Diff = รายการสิ่งที่เปลี่ยนไปจากจุดเซฟก่อนหน้า
- Branch = เส้นทางการเล่นแยก เพื่อลองเล่นแบบไม่กระทบเส้นหลัก
- Push = ส่งจุดเซฟขึ้นเว็บกลาง เช่น GitHub
- Pull = ดึงของล่าสุดจากเว็บกลางมาในเครื่อง
- Merge = รวมงานจากเส้นหนึ่งเข้ากับอีกเส้นหนึ่ง
- Deploy = เอาแอปวิ่งจรันใหม่ไปให้ผู้ใช้จริง ใช้ ไม่ใช่ commit

## กฎ Git สำหรับเจ้าของ

- ห้าม commit ก่อนทดสอบผ่าน
- ห้าม force push หรือ reset --hard ถ้าไม่เข้าใจ
- ห้ามลบ branch หรือแก้ conflict เอง
- ก่อนงานใหญ่ให้มี commit ล่าสุดที่ใช้งานได้
- ถ้าเห็นข้อความ conflict, rejected, detached HEAD, force push: ให้หยุดและส่งข้อความ/ภาพให้ Cline วิเคราะห์ก่อน

## Flow ปกติแบบปลอดภัย

1. Cline ทำงาน
2. Cline รัน validation
3. เจ้าของทดสอบ
4. Cline สรุป git diff เป็นภาษาคน
5. เจ้าของอนุมัติ commit
6. Cline commit หรือบอกวิธีกด commit
7. Cline ยืนยัน commit hash/message
8. Cline อัปเดต HANDOFF.md

## Prompt พร้อมใช้

### ตรวจงานก่อน commit
\"ตรวจงานก่อน commit. สรุปว่า file อะไรเปลี่ยนไปเป็นภาษาคน และบอกว่ามีอะไรเกิน scope ไหม\"

### อนุมัติ commit
\"APPROVE COMMIT. ทำ commit และบอกผลลัพธ์\"

### สร้าง branch สำหรับงานเสี่ยง
\"สร้าง branch ใหม่สำหรับงานเสี่ยงก่อนลงมือ\"

### ตรวจสถานะ Git
\"ตรวจสถานะ Git ตอนนี้ให้ฉันฟังแบบไม่เข้าใจโค้ด\"

### ขอให้ย้อนกลับอย่างปลอดภัย
\"ขอย้อนกลับไป commit ล่าสุดอย่างปลอดภัย. ให้เสนอแผนก่อน ห้ามทำจริงจนกว่าฉันจะอนุมัติ\"

## คำที่เจ้าของต้องรู้เพิ่มเติม

- Conflict = โค้ดสองเส้นพยายามแก้บรรทัดเดียวกัน พร้อมกัน
- Rejected = Git ปฏิเสธการ merge/apply
- Detached HEAD = ยังอยู่ในจุดโค้ดเฉพาะ ไม่ได้แก้ branch ใด ๆ
- Force push = บังคับส่งโค้ดที่แทนที่ history เดิม เสี่ยงทำให้คนอื่นเสียโค้ด
