# คู่มือฉุกเฉินสำหรับเจ้าของโปรเจกต์

## เมื่อแอปรันไม่ได้

1. ห้ามทำ: ห้ามแก้โค้ดเอง, ห้ามรันคำสั่ง git ที่ไม่รู้จัก
2. เก็บข้อมูล: บันทึกข้อความ error หรือ screenshot ไว้
3. Prompt ส่ง Cline: \"แอปรันไม่ได้ ข้อความ error คือ [ใส่] ฉันรันคำสั่ง [ใส่] แล้วเกิด [ใส่] ให้ Cline ช่วยวิเคราะห์\"
4. เกณฑ์หยุด: ถ้า Cline ขอแก้โค้ด ให้รออนุมัติก่อน

## เมื่อหน้าเว็บขาว

1. ห้ามทำ: ห้ามรีเฟรชบังคับหลายครั้ง
2. เก็บข้อมูล: URL, browser, ข้อความ error, screenshot
3. Prompt ส่ง Cline: \"หน้าเว็บขาวที่ [URL] ข้อความ error [ใส่] เบราว์เซอร์ [ใส่] ให้ Cline ช่วยวิเคราะห์\"
4. เกณฑ์หยุด deploy: ถ้าเป็น production ให้หยุดใช้งานทันที

## เมื่อ Cline บอก test/build fail

1. ห้ามทำ: ห้ามแก้ test ด้วยการลดเกณฑ์ ห้ามปิด lint เพื่อให้ผ่าน
2. เก็บข้อมูล: ข้อความ error เต็ม, วิธีรัน, ผลลัพธ์
3. Prompt ส่ง Cline: \"Cline บอก test/build fail. ข้อความ error คือ [ใส่] ฉันรัน [ใส่] แล้วเกิด [ใส่] Cline ช่วยอธิบายและเสนอ fix plan\"
4. เกณฑ์หยุด: ถ้า Cline ไม่ชัดเจน ขอให้ Cline อธิบายง่าย ๆ

## เมื่อ Cline ขอแก้ database/auth/payment

1. ห้ามทำ: ห้ามอนุมัติทันที ห้ามแก้ schema เอง
2. เก็บข้อมูล: สรุปว่า Cline ต้องการแก้อะไร
3. Prompt ส่ง Cline: \"Cline ต้องการแก้ [ใส่] ขอเสนอ plan, risk, rollback plan ก่อน ฉันยังไม่อนุมัติ\"
4. เกณฑ์หยุด deploy: ห้าม deploy production เด็ดขาดถ้ายังไม่ได้อนุมัติ

## เมื่อเผลอสั่งงานผิด

1. ห้ามทำ: ห้ามรอเฉย ๆ ห้ามแก้ไขเพิ่มโดยไม่บอก Cline
2. เก็บข้อมูล: สั่งอะไรไป, ผลที่เกิด
3. Prompt ส่ง Cline: \"ฉันเผลอสั่ง [ใส่] ไปแล้ว ส่งผล [ใส่] Cline ช่วยดูว่าจะยังไงดี\"
4. เกณฑ์หยุด: ถ้าทำผิดแล้ว หยุดทำต่อ

## เมื่อโค้ดพังหลังเปลี่ยนงาน

1. ห้ามทำ: ห้าม commit โค้ดที่พัง, ห้าม push
2. เก็บข้อมูล: สั่งอะไรก่อนพัง, ข้อความ error
3. Prompt ส่ง Cline: \"โค้ดพังหลังจาก [ใส่] ข้อความ error [ใส่] Cline ขอย้อนกลับไป commit ล่าสุดอย่างปลอดภัย\"
4. WeChat: บอก Cline ว่าอย่า force push

## เมื่อ Git conflict

1. ห้ามทำ: ห้ามแก้ conflict เอง ห้าม force push
2. เก็บข้อมูล: ข้อความ conflict เต็ม, ไฟล์ที่ conflict
3. Prompt ส่ง Cline: \"Git conflict ที่ไฟล์ [ใส่] ข้อความ error [ใส่] Cline ช่วยวิเคราะห์และเสนอวิธีแก้\"
4. เกณฑ์หยุด: ห้าม commit จนกว่า conflict จะแก้เสร็จ

## เมื่อ deploy แล้วผู้ใช้เจอปัญหา

1. ห้ามทำ: ห้าม deploy เพิ่มทันทีโดยไม่แก้ไข
2. เก็บข้อมูล: ผลกระทบ, จำนวนผู้ใช้, ข้อความ error
3. Prompt ส่ง Cline: \"deploy แล้วผู้ใช้เจอ [ปัญหา] ต้อง rollback หรือไม่? ขอเสนอแผน rollback\"
4. WeChat: ต้องอนุมัติก่อน rollback

## เมื่อสงสัยว่า secret/API key หลุด

1. ห้ามทำ: ห้ามแปะ secret ใน chat หรือ docs ห้ามแก้ repo เอง
2. เก็บข้อมูล: สรุปว่า secret อะไร, ตรงไหน, อาจหลุดไปไหน
3. Prompt ส่ง Cline: \"สงสัยว่า secret/API key หลุดใน [ใส่] Cline ช่วยสแกน repo หาจุดรั่วและเสนอ plan แก้ไข\"
4. WeChat: หยุดใช้งานทันที, เปลี่ยน key

## กติกาสำคัญ

- ห้ามแปะ secret, password, API key ลงใน chat หรือ docs
- ถ้า Cline แสดง secret: บอก \"หยุด, ฉันเห็น secret แล้ว ให้ Cline ลบออก\"
